# פרויקט 15 - אתר חדשות SPA (React + Vite)

בפרויקט הזה נבנה אפליקציית ווב מודרנית מקומפוננטות, ונחבר יחד את כל מה שלמדנו עד עכשיו: קומפוננטות ו-props, רינדור מותנה ולולאות, `useState`, `useEffect`, `useContext`, `useRef` ו-custom hooks.

**מה בונים:** אתר חדשות בסגנון SPA (Single Page Application). האתר בנוי מקומפוננטות, וכל המסכים מוצגים בעמוד אחד: המעבר ביניהם נעשה ברינדור מותנה לפי ערך שנשמר ב-`useState`.

- **דף חדשות ראשי:** מציג את הכתבות בכרטיסים. בכל כרטיס: `author` (שם הכתב או המקור), `title` (כותרת) ו-`urlToImage` (תמונה).
- **דף כתבה מורחב:** נפתח בלחיצה על כרטיס. מציג `description` (תיאור קצר), `content` (תוכן מלא) ו-`urlToImage` (תמונה).
- **דף יצירת כתבה:** טופס להוספת כתבה ידנית (כותרת, כותב, תיאור, תוכן ותמונה). אחרי השליחה מופיעה הודעת הצלחה, והכתבה החדשה מופיעה בראש הרשימה בדף הראשי.
- **סרגל ניווט:** קומפוננטה שמופיעה בכל המסכים ומאפשרת לעבור בין הדף הראשי לדף היצירה. הדף המורחב נפתח מהכרטיס.
- **עיצוב:** האתר יעוצב בצורה מודרנית, נעימה וברורה.

## איך מתחילים

1. לוחצות למעלה על **Use this template** ← **Create a new repository**, ויוצרות ריפו משלכן.
2. עושות `git clone` לריפו החדש ופותחות אותו ב-VS Code.
3. בטרמינל מריצות פעם אחת: `npm install` (צריך Node בגרסה 20.19 ומעלה. בודקות עם `node -v`).
4. נרשמות לאתר [newsapi.org](https://newsapi.org/) ומקבלות מפתח API אישי (חינם). את המפתח שומרות בקובץ `.env` - ההסבר בשלב 1.
5. מריצות `npm run dev` ופותחות את הכתובת שמופיעה בטרמינל (בדרך כלל `http://localhost:5173`). הדף מתעדכן לבד בכל שמירה.

> הפרויקט נוצר עם `npm create vite@latest` (תבנית React עם ESLint), כמו שעבדנו בכיתה. התיקיות והקבצים כבר מוכנים - צריך רק למלא אותם.

## מבנה הפרויקט

הקבצים מסודרים לפי קומפוננטות, hooks ו-context בתיקיות נפרדות, כדי לשמור על קוד נקי וברור:

```
src/
├── main.jsx                 ← מוכן: <NewsProvider><App /></NewsProvider>
├── config.js                ← שלב 1: הכתובת של ה-API עם המפתח מ-.env
├── hooks/
│   └── useFetch.js          ← שלב 2: custom hook
├── context/
│   ├── NewsContext.js       ← שלב 3: createContext
│   └── NewsProvider.jsx     ← שלב 3: stories, loading, addStory
├── components/
│   ├── NewsStory/           ← שלב 4: כרטיס של כתבה אחת
│   ├── NewsList/            ← שלב 5: רשימת הכתבות
│   ├── StoryDetails/        ← שלב 6: הדף המורחב
│   ├── CreateStory/         ← שלב 7: טופס יצירת כתבה
│   └── Navbar/              ← שלב 8: סרגל הניווט
├── App.jsx                  ← שלב 8: בחירת המסך
├── assets/default-news.svg  ← תמונת ברירת מחדל
└── index.css                ← עיצוב כללי
```

לכל קומפוננטה יש קובץ `*.module.css` משלה לעיצוב.

## מה בודקים בכל נושא

- **Props:** `NewsStory` מקבלת `author`, `title`, `urlToImage` ופונקציית לחיצה. Context משמש לרשימה כולה, ו-props לנתוני כרטיס בודד.
- **לולאות:** הרשימה נבנית מהמערך עם `map` ו-`key` ייחודי לכל כתבה.
- **רינדור מותנה:** `"Loading..."` בזמן הטעינה, בחירת המסך לפי הערך ב-`useState`, הודעת הצלחה אחרי יצירת כתבה, ותמונת ברירת מחדל כשאין `urlToImage`.
- **useState:** המסך הנוכחי, הכתבה שנבחרה והודעת ההצלחה.
- **useEffect:** הקריאה ל-API והבאת המידע מתבצעות ברינדור הראשון (מערך תלויות ריק). ה-effect נמצא בתוך `useFetch`.
- **custom hook:** `useFetch(url)` מחזיר `{ data, loading }`. הוא לא יודע כלום על חדשות ואפשר להשתמש בו שוב בכל פרויקט.
- **useContext:** `NewsProvider` קורא ל-`useFetch`, מוסיף ל-`data` את הכתבות שנוצרו ידנית, ומעביר דרך ה-Context את `stories`, `loading` ו-`addStory`. כל קומפוננטה שצריכה אותם קוראת ל-`useContext` ישירות.
- **useRef:** בטופס היצירה כל שדה מחובר ל-ref. בשליחה קוראים את הערכים מ-`ref.current.value` (ואת הקובץ מ-`ref.current.files`), יוצרים אובייקט כתבה בעל אותם שדות כמו ב-API, וקוראים ל-`addStory`. אחרי השליחה מנקים את השדות וממקדים את הסמן בשדה הראשון עם `ref.current.focus()`.

## איך זה יעבוד?

- נשתמש בשירות החדשות [newsapi.org](https://newsapi.org/) כדי להביא חדשות אמיתיות.
- כדי לעבוד עם השירות יש להירשם באתר ולקבל מפתח API אישי.
- את המפתח נשמור בקובץ `.env`, וקובץ ה-JS `src/config.js` יקרא אותו משם.
- חשוב להוסיף את הקובץ `.env` ל-`.gitignore`, כדי שגיט יתעלם ממנו (המפתח צריך להישאר פרטי).
- כדי לחסוך בקריאות מיותרות ל-API, נשמור את המידע ב-LocalStorage (קאשינג). בכל טעינה נבדוק קודם אם יש נתונים ב-LocalStorage, ורק אם אין, נפנה ל-API. הבדיקה הזו נעשית בתוך `useFetch`.
- כתבה שנוצרת ידנית נשמרת ברשימה שב-Context ולא נשלחת ל-API. לכן היא נעלמת ברענון הדף. (בונוס: שמרו אותן גם ב-LocalStorage.)

## שלבים

### שלב 1: מפתח ה-API

1. בתיקייה הראשית של הפרויקט (ליד `package.json`) יוצרות קובץ חדש בשם `.env`, ומעתיקות אליו את התוכן של `.env.example` עם המפתח שלכן:
   ```
   VITE_NEWS_API_KEY=המפתח-שלכן
   ```
   Vite נותן לקוד בדפדפן רק משתנים שהשם שלהם מתחיל ב-`VITE_`.
2. מוסיפות ל-`.gitignore` שורה עם `.env`, כדי שהמפתח אף פעם לא יעלה ל-GitHub.
3. ב-`src/config.js` קוראות את המפתח עם `import.meta.env.VITE_NEWS_API_KEY` ובונות איתו את `NEWS_URL` (הכתובת כבר כתובה שם).

> אחרי שינוי ב-`.env` צריך לעצור את `npm run dev` ולהריץ אותו שוב.
> המפתח החינמי של newsapi עובד רק מהמחשב שלכן (`localhost`), ולכן האתר עובד ב-`npm run dev`.

### שלב 2: `useFetch` (בקובץ `hooks/useFetch.js`)

custom hook שמבצע את הקריאה ל-API ומחזיר את הנתונים ואת מצב הטעינה.

- `useFetch(url)` מחזיר אובייקט `{ data, loading }`.
- `loading` הוא `true` עד שמגיעה תשובה, ו-`data` הוא ה-JSON שה-url החזיר (בשלמותו - בלי לבחור ממנו שדות. ה-hook לא יודע כלום על חדשות).
- הקריאה נעשית ב-`useEffect` עם מערך תלויות ריק `[]`, כלומר פעם אחת ברינדור הראשון.
- קודם בודקות אם התשובה של ה-url הזה כבר שמורה ב-LocalStorage. אם כן - משתמשות בה ולא קוראות ל-`fetch`. אם לא - קוראות ל-API ושומרות את התשובה ב-LocalStorage (`JSON.stringify`) וגם ב-state.

רמז: את הכתובת עצמה (`url`) אפשר להשתמש בה כמפתח של LocalStorage. ואפשר לקרוא את LocalStorage כבר בערך ההתחלתי של ה-state: `useState(() => ...)`.

### שלב 3: `NewsContext` ו-`NewsProvider` (בתיקייה `context/`)

ה-Context שמחזיק את רשימת הכתבות ואת הפונקציה להוספת כתבה, ונגיש לכל האפליקציה.

- ב-`NewsContext.js`: `export const NewsContext = createContext(null)`.
- ב-`NewsProvider.jsx`:
  - קוראות ל-`useFetch(NEWS_URL)` (מ-`config.js`). הכתבות מה-API נמצאות ב-`data.articles`.
  - שומרות ב-`useState` את הכתבות שנוצרו ידנית.
  - `stories` = הכתבות שנוצרו ידנית (החדשה ראשונה) ואחריהן הכתבות מה-API.
  - `addStory(story)` מוסיפה כתבה חדשה לראש הרשימה. היא לא נשלחת ל-API.
  - מחזירות `<NewsContext.Provider value={{ stories, loading, addStory }}>{children}</NewsContext.Provider>`.

`NewsProvider` כבר עוטף את `App` בקובץ `main.jsx`.

### שלב 4: `NewsStory` - כרטיס של כתבה

קומפוננטה שמציגה כרטיס של כתבה אחת. מקבלת את הנתונים ב-props ופונקציה ללחיצה על הכרטיס:

```jsx
<NewsStory author="..." title="..." urlToImage="..." onClick={() => ...} />
```

- מציגה תמונה (`<img>`), כותרת וכותב.
- כשאין `urlToImage` (הוא `null`) - מציגה תמונת ברירת מחדל. יש אחת מוכנה: `src/assets/default-news.svg` (מייבאות אותה עם `import`).
- לחיצה על הכרטיס קוראת ל-`onClick`.

### שלב 5: `NewsList` - רשימת הכתבות

- קוראת את `stories` ו-`loading` עם `useContext(NewsContext)`.
- בזמן הטעינה מציגה `Loading...`.
- אחרת עוברת בלולאה (`map`) על הכתבות ומציגה `NewsStory` לכל כתבה, עם `key` ייחודי.
- מקבלת prop אחד: `onSelectStory`. בלחיצה על כרטיס קוראות לה עם אובייקט הכתבה: `onSelectStory(story)`.

### שלב 6: `StoryDetails` - הדף המורחב

- מקבלת prop אחד: `story` (אובייקט הכתבה).
- מציגה את `description`, את `content` ואת התמונה (או את תמונת ברירת המחדל). אפשר כמובן להציג גם את הכותרת והכותב.

### שלב 7: `CreateStory` - טופס יצירת כתבה

- טופס (`<form>`) עם שדות לפי הסדר: **Title**, **Author**, **Description**, **Content**, ושדה קובץ (`<input type="file">`) ל-**Image**. לכל שדה יש `<label>` שמחובר אליו (`htmlFor` + `id`).
- כל שדה מחובר ל-ref עם `useRef`.
- בשליחה:
  - `event.preventDefault()` - הדף לא נטען מחדש.
  - קוראות את הערכים מ-`ref.current.value`, ואת הקובץ מ-`ref.current.files[0]`.
  - יוצרות אובייקט כתבה עם אותם שדות כמו ב-API: `{ author, title, description, content, urlToImage }`. את `urlToImage` יוצרות מהקובץ, למשל עם `URL.createObjectURL(file)`. התמונה לא חובה: אם לא נבחר קובץ, `urlToImage` הוא `null`.
  - קוראות ל-`addStory(story)` (מ-`useContext(NewsContext)`).
  - מציגות הודעת הצלחה, למשל `Story created successfully!`.
  - מנקות את השדות וממקדות את הסמן בשדה הראשון (Title) עם `ref.current.focus()`.

### שלב 8: `Navbar` ו-`App`

- **Navbar:** סרגל הניווט, בתוך `<nav>`. יש בו שני כפתורים: `Home` ו-`Create Story`. הוא מקבל prop בשם `onNavigate` וקורא לו עם שם המסך.
- **App:** מחזיקה ב-`useState` את המסך הנוכחי (`"home"` / `"details"` / `"create"`) ואת הכתבה שנבחרה, ומציגה את המסך המתאים ברינדור מותנה:
  - `Navbar` מוצג תמיד, בכל המסכים.
  - `"home"` ← `<NewsList onSelectStory={...} />`. לחיצה על כרטיס שומרת את הכתבה ועוברת ל-`"details"`.
  - `"details"` ← `<StoryDetails story={...} />`.
  - `"create"` ← `<CreateStory />`.
- את ה-API קוראים פעם אחת בלבד (ב-`NewsProvider`), גם כשעוברים בין המסכים הרבה פעמים.

## בונוס

כתבות שנוצרו ידנית נעלמות ברענון הדף. שמרו אותן גם ב-LocalStorage, כך שאחרי רענון הן עדיין יופיעו בראש הרשימה.

## תזכורת חשובה

ה-API שבו נשתמש מוגבל בכמות הקריאות, לכן חשוב:

- לא לשלוח בקשות מיותרות.
- להשתמש תמיד ב-LocalStorage לפני פנייה ל-API.
- לשמור את מפתח ה-API בצורה מאובטחת (בקובץ `.env` שמוחרג מגיט).

> ב-`npm run dev` הפרויקט רץ בתוך `<StrictMode>`, ש-React מריץ בו כל `useEffect` פעמיים כדי למצוא באגים. לכן בטעינה הראשונה (לפני שיש נתונים ב-LocalStorage) אפשר לראות 2 בקשות בלשונית Network. זה קורה רק במצב פיתוח. אחרי שהנתונים נשמרו - אין יותר בקשות.
> כדי לקבל חדשות עדכניות, מוחקות את הנתונים השמורים: DevTools ← Application ← Local Storage.
